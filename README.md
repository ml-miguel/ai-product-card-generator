# AI-помощник для подготовки товарных описаний

Прототип сервиса на Python (FastAPI + GigaChat), который генерирует черновик карточки товара для B2B-интернет-магазина на основе технических данных о приборе.

## 🚀 Стек
- **Python 3.10+**
- **FastAPI** — веб-фреймворк для API.
- **Pydantic** — валидация входящих и исходящих данных.
- **GigaChat (LangChain)** — LLM для генерации контента.
- **Uvicorn** — сервер для запуска приложения.

## 📦 Установка и запуск

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/ml-miguel/ai-product-card-generator.git
   cd ai-product-card-generator
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
3. Создайте файл `.env` в корне проекта и добавьте ваш токен GigaChat (формат в `.env.example`):
   ```bash
   GIGACHAT_CREDENTIALS=your_access_token
4. Запустите сервер:
   ```bash
   uvicorn main:app --reload
5. Откройте Swagger UI в браузере: `http://127.0.0.1:8000/docs`.

## 🧠 Принятые решения и промпты
1. **Жесткий System Prompt:** Чтобы исключить галлюцинации (выдумывание характеристик), в системном промпте прописано жесткое правило: «_Использовать ТОЛЬКО технические характеристики из входного JSON. При отсутствии данных писать "данных нет"_».
2. **Ограничение длины:** В промпт добавлено требование к объему SEO-описания (строго 800–1200 символов) с указанием структуры из 3-4 абзацев. Без этого LLM склонна писать короткие тексты.
3. **Pydantic-валидация:** Ответ от LLM парсится и валидируется через `ProductOutput`. Если нейросеть забудет поле или вернет не тот тип данных, Pydantic выбросит ошибку, и сервис вернет 500, не отдавая «сломанный» JSON клиенту.
4. **Очистка JSON:** Написан метод `extract_json`, который через регулярные выражения вытаскивает JSON из ответа нейросети, даже если она обернула его в markdown-блоки (`json ...`).

## ⚠️ Ограничения и возможные улучшения
**Ограничения:**

* Сервис синхронный (GigaChat вызывается через `llm.invoke`). В условиях высокой нагрузки лучше перейти на `async/await`.
* Нет базы данных — каждый запрос обрабатывается независимо.
* Нет автоматического перевода цен из XML (используется только то, что передано в JSON).

**Возможные улучшения:**

* Добавить сохранение результатов в БД или отправку в CMS по API.
* Настроить кэширование (Redis), чтобы не генерировать карточку заново при повторном запросе того же товара.
* Добавить автотесты (pytest) для эндпоинта.
* Использовать `few-shot` промптинг (дать модели 1-2 примера идеальных карточек), чтобы еще точнее управлять стилем.
